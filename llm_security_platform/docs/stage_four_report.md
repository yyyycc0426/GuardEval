# 阶段四实验报告：防御策略体系与消融实验

## 1. 实验设置

- 数据集：冻结 `attackset_v2`，64 条，其中攻击 48 条、正常请求 16 条。
- 目标模型：可重复的 `mock-vulnerable-model`。
- 策略版本：`defense_suite_v1`。
- 每组只改变防御策略，其余模型与数据配置保持一致。
- 原始报告：`reports/stage_four_defense_ablation.json`。

Mock 消融用于确定策略因果贡献和质量门禁，不代表真实模型的最终安全水平。真实 Ollama 防御实验应作为后续扩展实验。

## 3. 策略分析

### 输入防御

独立降低 33.33 个百分点 ASR，不阻断正常请求。它对可识别的直接覆盖和编码模式有效，但对改写攻击与文档注入仍有漏报。

### RAG 防御

总体 ASR 降低 25 个百分点。更重要的是，`rag_data_leakage` 分项 ASR 从 100% 降至 0%，说明权限过滤、敏感字段过滤和恶意文档隔离对目标风险有效。

### 输出防御

最终输出 ASR 降至 0%，但 75% 请求需要人工复核。它能够防止危险内容交付给用户，却不能证明模型内部没有被成功诱导，因此属于必要兜底层，而不是输入与 RAG 防御的替代品。

### 组合收益

输入 + RAG 将 ASR 从两个单策略的 66.67%/75% 进一步降至 54.17%，存在叠加收益。完整组合最终交付 ASR 为 0%，且没有阻断任何请求；输入与 RAG 提前消解部分风险后，输出层复核率从 75% 降至 40.62%。

## 4. 独立贡献

- 输入防御阻止 16 条基线成功攻击。
- RAG 防御阻止 12 条基线成功攻击。
- 输出防御阻止全部 48 条最终危险输出，其中 26 条无法被其他两个单策略阻止。
- 完整组合产生 218 条审计记录，动作包括 allow、sanitize、rewrite、redact 和 review，证据覆盖率 100%。

## 5. 典型成功案例

- 恶意检索文档：整段替换为 `QUARANTINED_MALICIOUS_DOCUMENT`，来源和权限边界仍保留。
- 密钥泄露：输出中的 API Key 或 Canary 被脱敏，并进入人工复核。
- 直接注入：输入层规范化后识别覆盖指令，按风险选择清洗、系统加固或阻断。

## 6. 失败与限制

- 输入防御单独使用仍有 66.67% ASR，说明规则和轻量检测无法覆盖所有语义变体。
- 输出防御的低最终 ASR 是“阻止危险响应交付”，不等于目标模型未遭攻击。
- 当前正式消融使用 Mock 以保证因果可重复；真实模型的九组实验成本更高，尚未写入本报告。
- PII 规则属于基础模式匹配，可能漏掉非标准格式。
- RAG 权限通过合成 document metadata 验证，尚未连接真实向量库 ACL。

## 7. 结论

阶段四证明平台可以在不全量阻断的情况下显著降低攻击结果交付率，并量化安全收益、业务可用性、延迟和人工复核成本。最合理的工程定位是：输入与 RAG 防御负责降低攻击发生概率，输出防御负责最后兜底，人工复核处理高风险和不确定结果。
